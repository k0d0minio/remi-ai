## What changed

- `packages/services/src/files/`: the fourth seam — `FileStore`, `registerFileStore()`, a default
  that stores nothing (`isFileStoreConfigured()` false), and the rules: the type allow-list and the
  10 MB cap on every upload grant and again on the stored object (`acceptStoredFile` removes an
  object that fails), five-minute read links. `adapters/vercel-blob.ts` is the only server file
  naming the vendor; `adapters/vercel-blob-client.ts` + `client.ts` are the browser uploader, so the
  console never names it either. New subpaths `./files` and `./files/client` (package.json +
  tsup, adjacent).
- `packages/services/src/shared/files.ts`: the isomorphic half — `documentFileTypes`,
  `MAX_DOCUMENT_FILE_BYTES`, `patientFilesPrefix`, `patientFileKey`, `documentKinds`,
  `documentTags`. `shared/patient.ts` gains `patientLinkPreviewParam`.
- `packages/services/src/db/`: `patient_documents` (cascade on the patient, `set null` on goal and
  recipe assignment, a check for the file/link shape and one for "one parent at most"), migration
  `0021_patient_documents.sql` generated by drizzle-kit — only the new table, no drift. Service
  `patient-documents/` (add link, add file, edit, remove, list newest first, owner) with tests
  written from the criteria. `deletePatient` sweeps the patient's store prefix before the row and
  refuses on a store failure — or when no store is configured and the patient has files.
- `BLOB_READ_WRITE_TOKEN`: `env.ts`, `turbo.json`, `.icm/docs/ENV.md` (§ Files, new),
  `apps/admin/.env.example`, `apps/web/.env.example`.
- `apps/admin`: `lib/files.ts` (`fileStoreReady()`, registration through `/server` — the copy
  `deletePatient` reads); `app/api/files/upload` (the grant — session, patient, key under the
  patient's prefix) and `app/api/files/[documentId]` (the operator's file opener); the Documents
  section (`document-section.tsx`) in « Dossier »; four actions with audit (`document.added /
  updated / removed`); « Voir comme la patiente » in the quick actions; the delete dialog now
  shows a refusal instead of redirecting past it.
- `apps/web`: the `documents` segment (nav, page, hidden when empty), `documents/[id]/route.ts`
  (token owns the document → 302 to a signed URL, `no-store`; anything else 404), documents under
  their recipe and beside their goal, recipe-tagged documents listed under Recettes (which now also
  shows for a patient with recipe documents and no assigned recipe), the preview marker
  (`lib/patient-link/preview.ts` + `proxy.ts`), copy in both locales.
- `.icm/docs/RETENTION.md`: documents and files in the held-data table, a section on where files
  live and who reads them, and the cascade.
- `packages/services/AGENTS.md`, `apps/admin/AGENTS.md`: the seam table, the entrypoints, the
  api routes.

## Notes for Release

- **Docs step owed:** add a « Files — 2026-09-24 » entry to `apps/docs/app/technical/decisions`:
  Vercel Blob behind the `FileStore` seam (D-18), a private store in an EU region (both fixed at
  creation), one prefix per patient, PDF / JPEG / PNG / WebP at 10 MB enforced by the seam on the
  grant and on the stored object, five-minute signed read links and no public URL, files removed
  before their row and swept before a patient is deleted, uploads from the browser under a grant
  (a 10 MB body cannot pass through a function), the upload-completed callback deliberately unused.
- **Operator setup before the smoke:** create a **private** Blob store in an **EU region** for
  preview (and one for production), and set `BLOB_READ_WRITE_TOKEN` on **both** the admin and the
  app projects — `env.sh audit --changed` reports `GAPS 2` for exactly that (declared in both
  `.env.example` files, no value yet on Vercel/admin and Vercel/app); the value is the operator's. Without it the console's upload is disabled (by design) and only links can be
  smoked.
- **Dependency audit — not this diff's:** `security-check.sh` reports 20 high/critical advisories
  when the lockfile moves; `pnpm audit` lists the identical set on `origin/main` (none through
  `@vercel/blob`). Already parked as the P0 chore `triage/dependency-audit-next-rce`. This run's
  gate calls ran with `--no-audit` on that basis (`error.log`).
- **Decisions Build made (spec gaps, small):** (1) the preview marker is a one-hour, HttpOnly,
  token-valued cookie set by the web proxy from `?apercu=1` — layouts cannot read search params, so
  a cookie is the only way the whole preview visit, across segments, stays unrecorded; it grants
  nothing. (2) `added_by` is `added_by_email` (text), for the reason the invitation's
  `invited_by_email` gives. (3) The operator opens a file through `/api/files/[id]` (a signed
  redirect), since the store is private. (4) Recettes now shows for a patient who has recipe
  documents but no assigned recipe.
- **Look closely at:** `apps/admin/app/api/files/upload/route.ts` (the grant's permission check)
  and `apps/web/app/[locale]/p/[token]/documents/[id]/route.ts` (the ownership check) — both are
  trust boundaries.

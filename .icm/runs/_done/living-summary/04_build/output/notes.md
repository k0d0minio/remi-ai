# Build notes: living-summary

- commits: feat(services): patient_summaries table + service behind the seam · feat(admin): living summary card on the patient page · docs: build notes + spec reconcile
- demo: none

## What changed

- `packages/services/src/db/schema.ts`: new `patient_summaries` — one row per patient
  (`patient_id` UNIQUE, `ON DELETE cascade`), `body`, timestamps. No `archivedAt`: the summary is a
  living value, history is the consultation notes' (decision #7). Own table, not a profile column,
  so the AI round's draft/validated state and the reviewed-at open question land as columns beside
  `body`, not a re-model.
- `packages/services/src/db/migrations/0009_left_shape.sql` + snapshot + journal: generated by
  `pnpm db:generate`. Additive `CREATE TABLE` only — applies over existing rows with no manual step.
- `models/patient-summary.ts`, `models/index.ts`, `shared/index.ts`: the `PatientSummary` type,
  re-exported isomorphically for the admin block.
- `db/services/patient-summaries/`: `getPatientSummary` (row or `null`) and `setPatientSummary`
  (upsert; whitespace clears; same-words is a no-op; `touchPatient` on every real write). Registered
  through `db/index.ts`, the Neon adapter registry, and exercised against the in-memory client.
- `shared/audit.ts` + `apps/admin/components/audit/vocabulary.ts`: `summary.updated` /
  `summary.cleared` with French labels and neutral intents.
- `apps/admin/lib/patients/actions.ts`: `setSummaryAction` — reads state before the write so the
  trail distinguishes a first draft/edit (`summary.updated`) from a clearing (`summary.cleared`)
  from a no-op.
- `apps/admin/components/patients/summary-block.tsx` + `vocabulary.ts`: one generous textarea, its
  own save, the patient-visible notice and § C's checklist as guidance — both French, from the
  vocabulary file.
- `apps/admin/app/(admin)/patients/[id]/page.tsx`: loads the summary and renders a "Résumé vivant"
  card directly under "Lien patient", above "Objectifs et consigne".

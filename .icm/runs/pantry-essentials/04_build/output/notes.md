## What changed

- `packages/services/src/db/schema.ts` + `migrations/0004_next_cable.sql`:
  `patient_pantry_essentials` — `item`, `why`, `position`, `archived_at`, a cascading
  `patient_id` FK and the shared timestamps. Additive: one `CREATE TABLE` plus its constraint,
  so it applies to a database holding existing rows with nothing to backfill.
- `db/adapters/neon.ts`: the collection name registered in the table registry — the one line
  that stops a service reaching for a collection the schema does not carry.
- `db/models/pantry-essential.ts` (+ models index, `shared/index.ts`): the type, re-exported to
  browser code the same way the other patient models are.
- `db/services/pantry-essentials/`: the callable surface — list active, list archived, add,
  update, move up/down, archive, restore, delete — plus its tests. Written against
  `patient-recommendations`, which is the same shape of per-patient child list; the reorder
  renumbers the run 0…n-1 rather than swapping two stored ranks, for the reason that service
  documents.
- `server/index.ts`: the seven functions and `PantryEssentialInput`. Not added to the `/db`
  barrel — no consumer imports them through that entrypoint, and a barrel line is a public-API
  commitment.
- `shared/audit.ts` + `apps/admin/components/audit/vocabulary.ts`: six `pantry.*` actions with
  French labels; only `pantry.deleted` carries a non-neutral intent.
- `apps/admin/lib/patients/actions.ts`: five server actions, each re-asserting the operator
  session and writing through `lib/audit.ts`.
- `apps/admin/components/patients/pantry-{list,item,add-form}.tsx` and the two cards on
  `/patients/[id]`.

## Notes for Verify

- **Reordering is audited here, and deliberately is not for recommendations.**
  `moveRecommendationAction` documents its silence ("a journal full of nudges is a journal
  nobody reads"); the spec asks for six audited writes on this list, so `pantry.reordered` has a
  writer. The alternative would have left a vocabulary entry with no reader, which the leanness
  rules forbid. Worth a second opinion: if the journal reads noisy in practice, the fix is to
  drop the action from both the vocabulary and the action, not to leave it dangling.
- **Card placement.** The spec says "directly after the recommendations card". It sits after the
  _archived_ recommendations card, so the recommendations pair is not split. Same block, one
  card later.
- Ran `vitest` in `packages/services` — 99 tests pass, including the 13 new ones. Format, lint,
  typecheck and build were left to the factory per `CONVENTIONS.md`; `tsc` is hook-blocked, so
  the type surface of the admin components is first proven by CI's `quality.yaml` and the Vercel
  preview.
- `pnpm install` had not been run in this container; it was needed for `drizzle-kit`. No
  dependency was added — `pnpm-lock.yaml` is unchanged.

# Build notes: profile-fields

- commits: `feat(services): profile-fields — five § A columns, the constraints narrowing` ·
  `feat(admin): profile-fields — the five fields on the profile form`
- demo: none

## What changed

- `packages/services/src/shared/patient.ts`: `cookingAffinities` — `yes | somewhat | no`, the
  closed set `likes_cooking` derives from. Not recorded is `null`, not a fourth member: that is the
  shape `consentChannel` already uses, and two spellings of "unknown" is the bug it avoids.
- `packages/services/src/db/schema.ts`: five columns — `dietary_regime`, `allergies`,
  `intolerances`, `food_budget` (all `not null default ''`) and `likes_cooking` (nullable).
  `constraints` keeps its name, type and content; only its comment narrows to the medical
  constraints that are neither allergy nor intolerance.
- `packages/services/src/db/migrations/0003_superb_baron_strucker.sql`: generated by
  `pnpm db:generate`, never hand-written. Five `ADD COLUMN`s with defaults — every existing row is
  valid the moment it runs, so no backfill and no manual step.
- `packages/services/src/db/models/patient-profile.ts` (+ the two barrels): the five fields and
  `CookingAffinity`, derived from the constant.
- `packages/services/src/db/services/patients/index.ts`: the five in `patientFields`, in the create
  defaults, and in the update path. `nullableChannel` was a `ConsentChannel`-shaped clone of
  `nullableText`; a second copy for the affinity would have been a third, so it is now one generic
  `nullableEnum` and the clone is deleted.
- `apps/admin/components/patients/vocabulary.ts`: `cookingAffinityLabels` (oui / un peu / non) and
  `dietaryRegimeSuggestions` — typing aids only, not a closed set.
- `apps/admin/components/patients/patient-form.tsx`: regime (Input + `datalist`), allergies and
  intolerances side by side above the narrowed « Contraintes médicales », then the affinity Select
  and the budget Input under preferences. The `datalist` sits outside `Field` on purpose — `Field`
  clones a single child to wire `aria-describedby`, so a second element would silently drop the
  hint from the accessibility tree.
- `apps/admin/lib/patients/actions.ts`: the five collected in `patientInputFrom`, the affinity
  narrowed by `asCookingAffinity` the same way the consent channel is. The audit call is untouched,
  so a profile edit still writes one `patient.updated` entry, unchanged in shape.

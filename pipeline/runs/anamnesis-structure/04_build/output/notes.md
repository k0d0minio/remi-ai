# Build notes: anamnesis-structure

- commits: `feat: anamnesis-structure — twelve categories replace the single blob`
- demo: none

## What changed

- `packages/services/src/shared/patient.ts`: `anamnesisCategories` — § B's twelve areas as stable
  English keys, in § B's order. The keys are what rows store, so the wording stays trimmable.
- `packages/services/src/db/schema.ts` + `migrations/0004_worthless_micromacro.sql`:
  `patient_anamnesis` — `patient_id` (cascade), `category`, `body`, timestamps, unique on
  `(patient_id, category)`. Purely additive; existing rows are untouched by it.
- `packages/services/src/db/models/patient-anamnesis.ts`: the model, types-only per the package
  rule, with `AnamnesisCategory` derived from the constant.
- `packages/services/src/db/services/patient-anamnesis/`: `listPatientAnamnesis` (rows that exist,
  in § B's order) and `setPatientAnamnesis` (one category, upsert-or-delete). An empty or
  whitespace-only body removes the row rather than storing `""`; an unknown category key is
  `invalid_input`; every write calls `touchPatient`.
- Barrels: `shared/index.ts` (constant + both types), `db/models/index.ts`, `db/index.ts`,
  `server/index.ts`.
- `packages/services/src/shared/audit.ts` + `apps/admin/components/audit/vocabulary.ts`:
  `anamnesis.updated`, with its French label and a neutral intent. Required by
  `apps/admin/AGENTS.md` — a write to a patient's record that skips the audit trail is incomplete.
- `apps/admin/components/patients/anamnesis-block.tsx`: all twelve categories, always, in § B's
  order; a category with nothing recorded reads as its heading and an em dash. The pencil opens a
  textarea for that category alone — the `RecommendationItem` / `NoteTimeline` pattern.
- `apps/admin/components/patients/vocabulary.ts`: `anamnesisCategoryLabels`, the § B wording. No
  French string is written in the component.
- `apps/admin/lib/patients/actions.ts`: `saveAnamnesisAction` — re-asserts the operator, sends one
  category, audits, revalidates.
- `apps/admin/app/(admin)/patients/[id]/page.tsx`: the block between Consultations and Profil.
- `apps/admin/components/patients/patient-form.tsx`: the legacy `anamnesis` field is unchanged in
  name, position and content; its hint now names it as the seed to redistribute, then empty.
- `delete-patient.tsx` + the page's danger-zone copy: the cascade now takes the anamnesis rows too,
  so the deletion warning says so.

## Acceptance criteria status

- [x] `patient_anamnesis` table + migration — `0004_worthless_micromacro.sql`, generated by
      `pnpm db:generate`. `CREATE TABLE` plus one `ADD CONSTRAINT`; nothing alters an existing
      table, so it applies to a populated database untouched.
- [x] `anamnesisCategories` lists § B's twelve in order, `AnamnesisCategory` derives from it, both
      re-exported through `@remi/services/shared` — the `patientSexes` / `cookingAffinities`
      pattern.
- [x] `vocabulary.ts` maps every category to its French § B label; the component renders those
      labels and hard-codes no French string.
- [x] The service lists in category order and upserts one category. Per-category isolation is
      asserted directly — the untouched row is compared object-for-object before and after a
      neighbouring write. Every write calls `touchPatient`.
- [x] An empty or whitespace-only body deletes the row; a patient with no anamnesis has zero rows
      and the page still renders all twelve categories, from the constant rather than from rows.
- [x] An unknown category is `invalid_input` and stores nothing.
- [x] The block sits between Consultations and Profil, all twelve in § B's order, label alone when
      empty.
- [x] Editing one category opens a textarea for it alone, saves through `saveAnamnesisAction`, and
      re-renders; no other category's text is sent or written.
- [x] `anamnesis` is unchanged in name, type, position and stored content; only its hint changed.
- [~] Tests: upsert, per-category isolation, clearing to deletion, unknown category and ordering
  all pass (12 new tests; 98/98 in the package). **The cascade half is not covered by an
  in-memory test** — `createMemoryDatabase()` has no foreign keys, so nothing there can prove a
  cascade. It is evidenced by the migration's `ON DELETE cascade`, identical to
  `patient_notes` and `patient_recommendations`, which are equally uncovered today. Making the
  memory client enforce foreign keys would change shared test infrastructure for every
  service — out of this run's scope, and worth its own chore if Verify wants the coverage.
- [x] `/p/[token]` is untouched, and the assertion lives where the query lives: a test on
      `getPatientByShareToken` writes three anamnesis rows and asserts the profile it returns
      carries none of them.

# Development

## Getting started

```bash
pnpm install
pnpm packages:build   # @remi/ui and @remi/services must exist before an app can compile
pnpm web:dev          # or admin:dev / marketing:dev / docs:dev / support:dev / demo:dev
```

`turbo run dev` declares `dependsOn: ["^build"]`, so a bare `pnpm dev` builds the packages first.
Run `pnpm packages:dev` in a second terminal to rebuild them on change.

## The factory owns the checks

Format, lint, typecheck and build are deterministic, non-AI work. They belong to Husky, CI and the
Vercel preview — not to a session's context window. An agent working in this repo is blocked from
running them locally by `.claude/hooks/block-local-checks.sh`: push, then read the result back from
the PR's check runs.

Which check runs where is one table, and it lives in `/CONVENTIONS.md` § "The factory owns the
checks — you do not". It is not copied here, because a second copy is how the two start
disagreeing.

## CI/CD

Every app deploys from its own Vercel project, gated by `turbo-ignore` so a change to `apps/docs`
does not rebuild `apps/web`. The Turborepo remote cache is shared between CI and Vercel, so the
package builds CI needs for `typecheck` are usually restored rather than recompiled.

## Delivery

Work reaches `main` through the pipeline. `/pipeline scope` settles a request with the operator into
`scope.md` and cuts the intake batch; then, per stub, `new` → `build` → `release` — one feature PR,
two human gates (Spec approved, Ready to merge), and a squash-merge that carries the run's record and
its archive. A `bug` / `tweak` / `chore` fast lane skips the front and ends in a PR the operator
merges; `knowledge` changes one of these pages outside a Release. See `.icm/CONTEXT.md`.

# REMI

The canonical reference for what REMI is, who it serves, and how it is built. Two halves, and
the split matters — the pipeline routes each stage to one or the other, never to "the docs".

## Business

Direction and product truth. What we are building and why now. The Scope and Define stages read
here for vocabulary and the why-now; Ship updates it when user-facing behaviour changes.

- **Initiatives** — the strategy the current work ladders up to
- **V2 scope** — the frozen feature list, and what is explicitly out of it
- **Roles** — who the product serves and what each of them can see and do

## Technical

How the repository is put together. The Build stage reads here to find where code lives and which
entrypoint to import; Ship updates it when the architecture changes.

- **Architecture** — repository structure, technology stack, how a request flows
- **Applications** — the six apps and what each is for
- **Packages** — `@remi/ui` and `@remi/services`, and their entrypoints
- **Development** — workflow, build system, CI/CD

## What is *not* here

Code conventions. They are canonical in [`CONVENTIONS.md`](https://github.com/k0d0minio/remi-ai/blob/main/CONVENTIONS.md)
at the repo root, plus the per-subtree `AGENTS.md` files — one home, so a rule can never disagree
with itself. This site covers product direction and architecture only.
